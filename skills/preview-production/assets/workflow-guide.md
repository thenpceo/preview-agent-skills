# Production Workflow

## A practical guide for leads, AI artists and producers

Use this project to keep the current work, its recipe, its review history and its approved version easy to find. Adapt the template to the job before production begins.

**The working path**

References: canvas exploration → selected images in a Character/Location/Prop version folder → review there → next folder for revisions.

Film shots: canvas work → nominated sequence item → internal review → configured final approval → producer delivery.

**Find your instructions**

## 01 — Project lead: set up the job

**1. Choose scripts and milestones**

Canvas categories describe the creative script. Each category contains that script's milestone canvases. The template has Script 1 and Script 2 categories, each with References, First Frames and Animation canvases. Use clear titles such as Script 1 · 01 References, Script 1 · 02 First Frames and Script 1 · 03 Animation. The numbers keep milestones in order under alphabetical sorting. Rename the script placeholders and adapt the milestones to the actual deliverables.

Multi-script example: Script A, Script B, Script C and Script D are four categories. Each contains its own References, First Frames and Animation canvases. Create four matching script shot lists, with deliverable sequences inside each.

One-script example: one Script A category contains Previz + Lookdev, Animation and Final VFX canvases. Work on its locations in named groups or rows inside each milestone canvas. References and character development belong in Previz + Lookdev; Animation includes the AI draft/animatic. Use shared versioned Character/Location/Prop entries across milestones, with review state recorded separately. The lead may authorize a location-specific continuation canvas when the volume requires it; keep that canvas inside the script category.

**2. Match the shot lists and sequences**

Start with one shot list per script. Inside it, create a sequence for each deliverable that needs its own review. For the basic template, use First Frames and Animation sequences; the References canvas feeds versioned library folders directly. Keep script names consistent between the category, canvases and shot list. Preserve an established location-based shot-list split unless a change is explicitly requested; reorganizing canvas categories does not require rebuilding sequences or review items.

For a job with extra deliverables, adapt the sequences: Previz, Lookdev Frames, Location Studies, Clean Plates, AI Draft and Final VFX are possible examples. One milestone canvas may support several deliverable sequences in the script's shot list. A location still, its 10-second video and a clean shot-angle plate need separate review items if each needs a separate decision. Optional world/scan work gets a slot only when it becomes a required deliverable.

**3. Define the shot breakdown before generating**

Agree stable shot IDs and descriptive names from the creative script with the director. Use those IDs in every phase, for example SCRIPT_A_SH01 · Wide or SCRIPT_A_SH08 · Table high angle. A Preview row number can change when items move; the stable title is the production identity. Keep the same shot ID in First Frames and Animation, with independent approval in each sequence.

Use one row for each logical film shot in every milestone. For SH07, write a short Description such as “Reveal the landscape, then pan to the performer. 7A and 7B required.” Attach both assets to that row; do not make separate 7A and 7B rows. One continuous video may cover several required storyboard states. Keep exact chosen takes and approvals per required part in Notes; alternate attempts are not additional requirements.

Create enough film items for the actual breakdown. Reusable references are reviewed in library version folders, without separate sequence rows for each view. A location wide and three detail views can all share the Location’s V001 folder.

**4. Brief and assign the work inside Preview**

Give shot lists and sequences a short purpose description where a native field is supported. Keep each shot Description/brief to one or two short sentences: the action/framing and required panels or parts. Put detailed instructions, source briefs, feedback, asset maps and approvals in Notes. Use technical fields for movement/lens intent, duration and interior/exterior, and link relevant Character/Location/Prop entries and source media.

Assign a current artist; confirm the internal reviewer, reference approver, final creative approver and producer/release owner for the job. A common arrangement has producer approval for references and director approval for shots, but the actual policy must be recorded. Add real priorities and due dates when known. Put the active canvas/group link, dependencies and next action in Notes. Start required work at To Do. Leave unknown owners or dates explicit rather than guessing them.

The lead's agent should build and maintain this breakdown directly in Preview. Production's Shotlist, Storyboard and Kanban views share the same records. A separate personal tracking UI should not become a competing shot list. Updating the creative Script does not automatically update production records; reconcile the breakdown after a script change.

**5. Set up reusable references early**

Create one master Character, Location or Prop entry per asset or scene extras group. Give it a stable name and useful description, link it to relevant shots, and rename its existing Default folder V001. These are typed reusable entries; their UI folders use Preview variations.

Artists work on the canvas, then save the images they like directly into V001 for review. Multiple pictures belong in one folder: additional character angles, location coverage or prop views can go together. Preserve original canvas takes and their source links. Folder membership does not establish approval; label each version’s current review state and exact accepted image set in the master entry’s Details/description.

For revisions, create V002, then V003 and onward beneath the same master. Put the revised images there, include still-valid views needed for that version’s set, and keep older folders and decisions. Shared assets are reviewed once and reused across shots. Existing References sequences remain history unless the lead authorizes their migration/removal; new references do not need sequence staging.

Named looks and states use sibling folders under the same master: Pajamas V001, Pajamas V002, Evening Clothes V001, or Night V001. Each look has its own version progression. Extra angles of the same look/version stay in that folder; added images are reviewed explicitly. These folder names implement the team’s version convention, not native automatic version history.

Use one Character for each background ensemble, such as Scene Extras or Seville Tourists. If four extras are needed, put their four images in that group’s V001 folder, or use one composite of the four. Both methods are valid; label members and performance roles when needed. Four images consume four model reference slots, not one; check the chosen model’s limit. Keep individually required principal roles distinct. Attach approved voice sources for speaking roles when appropriate and verify model binding.

**6. Prepare the canvases and handoff**

Use the template's Reference Sandbox, Archive and dated R00/R01 groups as a starting layout. In a reference canvas, the LOC, CHAR and PROP groups separate the work. In First Frames and Animation, SH01, SH02 and SH03 groups demonstrate shot passes. Add or remove unused sample groups and review items deliberately to match the real job.

Replace [DATE], [ScriptName] and [Initials]. ScriptName identifies the creative script. Use a separate location or item name when labeling work groups and rows. Keep groups flat: Preview does not nest groups. Paste headings where useful and use sticky notes for the brief, active work index and handoff. Dates and initials belong on round groups, not new daily canvases.

Keep canvases across days. Date the groups and review packages. Versioned library folders provide the shared source across milestone canvases; select the latest intended version and record its review state instead of copying yesterday's whole board. The lead owns the initial organization, and artists preserve that manual layout. Agents adapt confirmed unused placeholders within setup authorization; they ask before unrequested changes to established sequences, canvases, shot plans or library identities.

Choose the external storage root (for example, Suite) and delivery specs at kickoff. Keep a stable review index with Preview shot list/sequence links, the current review package and the last approved package. Save native projects and recipe files under the relevant scope and phase. Dates belong on review packages and work rounds.

## 02 — AI artist: make and submit work

**1. Start from the assigned item**

Open the right film shot list/phase sequence or reference master/version folder. Read the brief, current submission, last approved take/image set, unresolved comments and the latest intended reference folder’s review state. Check the intended canvas/group before starting. A new date, green tag or rightmost card does not establish the approved version.

**2. Work in a dated, initialed round group**

Use one named shot, character or reference view per row. Iterate left to right within that row. Use the Reference Sandbox for contextual sources or experiments; keep the production reference's exact library/take link visible. Preserve manual placement. Never use Organize group or Tidy up on an artist's layout.

Group name: YYYY-MM-DD - scope/item - R##[-B##] - initials. Example: 2026-10-13 - LOC-LocationA - R01-B02 - AB. Include the phase when a canvas contains multiple kinds of work. Use the date the pass began. Initials identify who made the pass; the current assignee and handoff identify who owns the next step.

R00 is the initial pass; R01 is a feedback revision. Start R01 only for items needing changes. Keep unchanged film approvals in their sequence slots and reference decisions tied to their exact folder/image sets. If a row becomes unwieldy after many attempts, continue the same round in B02 rather than making a huge endless row. Collapse finished groups or use the Archive area deliberately; retain history and its source links.

**3. Use canvas tags for working choices**

In Progress — actively being developed. Interesting — promising alternate. Rejected — discarded attempt. Needs Review — working review marker. Final — the artist's nominated choice. These are shared project tags; filter by Author when reviewing your own work. Final does not grant official approval.

**4. Submit references to version folders; film takes to sequence items**

For film takes, use Select for, choose the correct sequence and named item, or have your agent assign that existing take to the verified shot ID. Confirm the shot list as well as the sequence. Assignment keeps the work on its canvas; it does not require downloading and uploading another copy.

When a row has several required parts, assign their media to that same shot and label the parts in Notes. Track current and last-approved selections for each part. Do not mark the whole shot complete or approved until every required part has valid exact-version approval. Leave optional or parked parts explicit.

In Production/Shot Info, deliberately show the nominated take and set the item to Needs Review. Add what changed, what needs a decision and the exact version/take link. Record the candidate separately from the last valid approved take. Only nominate useful choices; the sequence is the review queue, not the full generation history.

For references, save selected images directly into V001 or the intended look/version folder, then review them there. Iterations use the next numbered folder. Preserve source images and older versions; do not create a reference sequence first. Record current submission, review feedback and last-approved image set in version-labeled master Details, with links to original file/canvas comments.

**5. Tag the latest intended reference version**

When building a new prompt, select the master Character/Location/Prop, then the latest populated version folder of the intended look and its required images. Compare version numbers, not dates or row order. Pajamas V002 is the latest pajamas look; it does not replace the base V002. Empty future folders are not usable references.

Preview’s picker lets you choose folders and images. A bare master tag is not guaranteed to choose the latest folder automatically, so artists select it explicitly and agents resolve the returned folder/attachment tokens. Check the selected images against model limits. Record folder name/index, exact attachment/take IDs, source roles and review state in the recipe. Historical generations retain their original references; explicitly pinned historical versions are recorded exceptions.

Latest means current working version, not automatically approved. Pending inputs are provisional; a run or release requiring approved inputs must verify the selected set’s decision. Do not silently fall back to an older approved folder.

**6. Keep the recipe and close the shift**

Use File View's prompt/settings and Reuse as the starting point. Save the effective prompt, model, settings, exact reference IDs and their roles, parent takes, start/end frames, motion or edit source, and the actual mode used. Recheck bindings after Reuse. Save external Blender, Photoshop or ComfyUI source revisions and recipe/workflow paths. A copied prompt alone is not a complete handoff.

Before logging off, update Notes with the current candidate, last approval, active group, recipe, open comments, dependency/blocker, next action and next owner. Include live job IDs if rendering is still underway. Another artist should be able to resume from Preview without searching private chats.

## 03 — Review: comments and decisions

**Leave feedback where the exact work lives**

For generated takes, open File View → Comments and pin feedback to the relevant part of the image. Canvas comments can be attached to a file or placed beside a group; drawings/arrows/boxes are available there. Use the Comments sidebar to find threads, reply in the original thread and tag the intended artist when useful.

File View pins are supported for generated takes, not reference/library images. For those sources, leave a canvas comment beside the exact reference and include its link/ID. Use Production Notes for film items and version-labeled master Details for reference decisions and next actions; keep visual discussion attached to the exact source take.

Write actionable feedback: “SH08 v003 — keep this framing; warm the lighting and remove the background person.” State what stays, what changes, who owns the change and whether it blocks approval. For video, include a timecode. Resolve a thread after the requested fix has been checked; a rendered new take does not by itself resolve feedback.

**Use official statuses on film sequence items; record reference version decisions in Details**

To Do → In Progress → Needs Review → Internally Approved → Final Approved.

Changes Requested — reviewer names the changes and next owner. Blocked — a dependency prevents progress; record what is needed and who can unblock it. Archived — historical/inactive item.

The designated internal reviewer grants Internally Approved. The configured reference approver grants final reference approval; the configured final creative approver grants final shot approval, each for the exact take, phase/state and current brief. Record the decision with reviewer, date and evidence link. The producer or agent may record that decision, but must not invent it. A reference or first-frame approval does not automatically approve a later animation.

For film revisions, nominate the new candidate to the same item and return it to Needs Review. For reference revisions, submit the next version folder and record pending review in the master’s Details. Keep prior approval evidence. If requested changes invalidate the earlier take for the current brief, explicitly mark it unsuitable for current delivery. An optional exploration can leave a valid approved take in place while the new candidate is reviewed.

**Keep two explicit choices in film Notes or version-labeled reference Details**

CURRENT SUBMISSION: exact take/version/link + current review status.

LAST APPROVED: exact take/version/link + phase + decision evidence + valid for current brief: yes/no.

Do not rely on the displayed alternate alone: it can change as someone browses takes. A reference baseline is the recorded exact folder/image set and approval evidence; this workflow does not depend on native folder approval fields or sequence locks.

## 04 — Producer: presentations and delivery

**Find film work through Production and reusable references through version folders**

Open the correct scope shot list. Use Shotlist for ownership/status/notes, Storyboard for a visual overview and Kanban or status filters for the review queue. Check the required phase sequence. Saved views such as Needs Internal Review, Awaiting Director, Changes Requested and Final Approved make repeat checks faster.

For a reference presentation, inspect the master entry’s latest intended folder, exact images and recorded review state. For a film presentation, take media from the exact nominated item/take. Check its version and status first. A review deck may contain pending work when clearly labeled “Needs Review” or “Internally Approved.” Record the Preview link and take/version alongside the slide or package manifest so feedback returns to the same asset.

Leave feedback in the take's comment thread, then summarize the action and owner in Production Notes. Use @mentions where appropriate. If a designated approver decision arrives in a meeting or elsewhere, record its source, date and exact take before changing the official status. A Slack notification or presentation link should point people back to this record.

**Package the approved work**

1. Check required coverage and valid configured final approval for each item being released. A review presentation and a final release have different approval requirements.

For a shot with multiple required assets, check the per-part asset map and package every required selected take. A sequence export may include only the displayed choice; verify coverage and use supported explicit file selection/download for missing parts.

2. Confirm the displayed/selected take matches the recorded approved ID before download or sequence export. Preview export follows the displayed choice. Use Selected takes for the intended package; stacked alternates are for an agreed internal handoff.

3. Save a new dated, versioned Suite package with the media, a manifest mapping filenames to Preview take IDs, approval evidence and recipe/source links. Include the agreed format, resolution, frame rate, audio and any review burn-in. Verify the files are readable.

4. Update the stable review index. Keep “current review” and “last approved” pointers separate, and retain earlier packages. Scope comes before date in filing: job / script-or-location / phase / package-round-date.

5. Track prepared, exported, sent and accepted separately. The producer owns release; exporting a ZIP does not prove delivery or acceptance.

For Final VFX, record the agency graybox source clip, shot bounds, frame rate and handles. Its real acting, timing, gestures, eyeline and camera behavior are the performance source. Approved environment references define appearance and space. Keep those input roles explicit in the shot brief and recipe.

## 05 — Names and handoffs

**Media filename**

Client_Script_Item_v###_YYYYMMDD.ext

Item is a stable shot ID or Type-Description: SH08, CHAR-PersonA, LOC-LocationA or PROP-Helmet. CHAR/LOC/PROP already identify references. Temporary exploration uses LOOKDEV-Description. Do not add a separate SHEET, REF or phase field. Use COMMON for assets shared across scripts.

Examples: CLIENT_ScriptA_SH08_v003_20261013.mp4 · CLIENT_ScriptA_LOC-LocationA-Wide_v004_20261013.png · CLIENT_ScriptA_CHAR-PersonA_v002_20261013.png.

Increment the version per named item across phases; use its creation date. The phase belongs in the sequence and Suite folder. Location based canvases do not change the Script field in filenames. Preview's export numbering may be positional; map exported names to stable IDs with the manifest rather than treating row numbers as script shot numbers.

**Copy this handoff into film Notes or version-labeled master Details**

CURRENT SUBMISSION: [take/version/link/status or none]

LAST APPROVED: [take/version/link/evidence; valid for current brief yes/no or none]

ACTIVE WORK: [canvas/group link; R##/B##; artist initials]

RECIPE / SOURCES: [prompt/settings/ref bindings; parent take IDs; native source/workflow paths]

OPEN FEEDBACK / BLOCKER: [comment links; dependency; who can resolve]

NEXT ACTION / OWNER: [specific next step; assigned artist/reviewer]

LIVE JOBS / UPDATED AT: [IDs if running; timestamp]

## 06 — Working with your agent

**Lead setup request**

“Read this workflow guide and the creative script. Set up [project] with one category per [script] and [milestone] canvases inside each. Build the matching script shot lists, deliverable sequences and named review items; fill briefs and references; assign the agreed artists. Preserve existing canvas layouts. Report missing decisions and verify the resulting records. Do not generate media.”

**Artist handoff request**

“Read [item]'s Notes, comments, current take and approved references. Recover its full recipe. Prepare the requested change in [canvas/group], preserve the last approved choice, and record the new candidate and handoff. Confirm the current model/settings/inputs and authorized run scope before generation.”

**Producer check request**

“Audit [shot list/phase] for current nominated takes, missing coverage, unresolved feedback and valid final approvals under the project policy. Prepare a review package or approved release manifest as specified, with exact take IDs and recipe links. Report exported, sent and accepted as separate states.”

Agents maintain the shared Preview records and reconcile the package manifest. They should use supported CLI/MCP tools for data and the normal UI for features absent from those tools. They must re-read shared Notes before edits, preserve manual layout and avoid treating tags, completion or provenance as human approval.

**Before the first production run**

The lead confirms actual names/counts, owners/reviewers, shot briefs, required reference coverage, Suite root and delivery specs. The template's sample people, locations, shots, durations and groups are examples; adapt them before relying on them for a real job.
