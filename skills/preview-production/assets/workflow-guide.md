# Production Workflow

## A practical guide for leads, AI artists and producers

Use this project to keep the current work, its recipe, its review history and its approved version easy to find. Adapt the template to the job before production begins.

**The working path**

Canvas exploration → nominated sequence item → internal review → configured final approval → approved library reference or producer delivery.

**Find your instructions**

01 Project lead: set up the job · 02 AI artist: make and submit work · 03 Review: comments and decisions · 04 Producer: presentations and delivery · 05 Names and handoffs · 06 Working with your agent.

## 01 — Project lead: set up the job

**1. Choose the work phases and scopes**

Canvas categories describe the work phase. Canvases describe the script or location being worked on. The template starts with References, First Frames and Animation, each containing Location/Script 1 and Location/Script 2. Replace those placeholders with the actual job names and create only the canvases needed.

Multi-script example: References / First Frames / Animation, each with Script A, Script B, Script C and Script D canvases. Four scripts have four matching shot lists.

Location example: Previz + Lookdev / Animation / Final VFX, with canvases named Location A, Location B and Location C. Work is split by location within one script. References and character development belong in Previz + Lookdev; Animation includes the AI draft/animatic. Adapt these examples to the actual job.

**2. Match the shot lists and sequences**

Create one shot list per chosen script or location scope. Inside it, create a sequence for each deliverable that needs its own review. For the basic template, use References, First Frames and Animation. Name the shot list and corresponding canvases consistently so anyone can find both.

For a job with extra deliverables, adapt the sequences: References, Previz, Lookdev Frames, Location Studies, Clean Plates, AI Draft and Final VFX are possible examples. A single canvas category can support several deliverable sequences in the matching shot lists. A location still, its 10-second video and a clean shot-angle plate need separate review items if each needs a separate decision. Optional world/scan work gets a slot only when it becomes a required deliverable.

**3. Define the shot breakdown before generating**

Agree stable shot IDs and descriptive names from the creative script with the director. Use those IDs in every phase, for example SCRIPT_A_SH01 · Wide or SCRIPT_A_SH08 · Table high angle. A Preview row number can change when items move; the stable title is the production identity. Keep the same shot ID in First Frames and Animation, with independent approval in each sequence.

Create enough items for the actual breakdown. Reference sequences use one item per independently reviewable character, prop, location view or visual state. A location wide and three detail views need four review items, even when all four will eventually belong to one Location variation.

**4. Brief and assign the work inside Preview**

For each item, fill the title, deliverable/purpose, brief and acceptance criteria. Add framing, angle, camera movement, lens intent, duration, dialogue/action and interior/exterior where relevant. Link the Character, Location and Prop entries it uses. Add relevant source media/reference links and explain their roles: appearance, composition, performance, timing or motion.

Assign a current artist; confirm the internal reviewer, reference approver, final creative approver and producer/release owner for the job. A common arrangement has producer approval for references and director approval for shots, but the actual policy must be recorded. Add real priorities and due dates when known. Put the active canvas/group link, dependencies and next action in Notes. Start required work at To Do. Leave unknown owners or dates explicit rather than guessing them.

The lead's agent should build and maintain this breakdown directly in Preview. Production's Shotlist, Storyboard and Kanban views share the same records. A separate personal tracking UI should not become a competing shot list. Updating the creative Script does not automatically update production records; reconcile the breakdown after a script change.

**5. Set up reusable references early**

Create the Character, Location and Prop entries before approved media exists. Give each a stable name and useful description, then link it to the shots that need it. They are typed reusable library entries, not canvas groups or ordinary folders.

Artists attach the exact approved media after the configured reference approver accepts that version. If the decision is missing, leave it in review and ask before promotion. Keep the original take on its canvas and assigned to its review item; library promotion gives it a reusable home without a second independent approval process. Until media is approved, the entry is a placeholder. Only the recorded approved attachments are the production reference set.

Give a shared asset one owning reference-review item. Other script/location scopes link to that approved library entry rather than creating duplicate approvals of the same version. A genuinely different wardrobe, lighting or narrative state can have its own review item and variation.

Variations describe deliberate states such as Day, Evening, Dinner wardrobe, Shirt Off or After Fight. Revision rounds belong in groups and review history. Several approved angles of the same location/state can belong to the same variation. Record exact current attachments so an obsolete image does not enter a prompt by accident.

Identifiable extras are Characters: create one stable identity per recurring extra, record associated locations, and link that person on relevant shots. Reuse the identity when they appear elsewhere. Attach an approved voice source for a speaking role when appropriate, and verify the chosen model actually binds it.

**6. Prepare the canvases and handoff**

Use the template's Reference Sandbox, Archive and dated R00/R01 groups as a starting layout. In a reference canvas, the LOC, CHAR and PROP groups separate the work. In First Frames and Animation, SH01, SH02 and SH03 groups demonstrate shot passes. Add or remove unused sample groups and review items deliberately to match the real job.

Replace [DATE], [ScriptName] and [Initials]. For a location based job, [ScriptName] in group labels means the location/work scope; the exported filename still names the creative script. Keep groups flat: Preview does not nest groups. Paste headings where useful and use sticky notes for the brief, active work index and handoff.

Keep canvases across days. Date the groups and review packages. Approved library references provide the shared source across phase canvases; use precise references instead of copying yesterday's whole board. The lead owns the initial organization, and artists preserve that manual layout. Agents adapt confirmed unused placeholders within setup authorization; they ask before unrequested changes to established sequences, canvases, shot plans or library identities.

Choose the external storage root (for example, Suite) and delivery specs at kickoff. Keep a stable review index with Preview shot list/sequence links, the current review package and the last approved package. Save native projects and recipe files under the relevant scope and phase. Dates belong on review packages and work rounds.

## 02 — AI artist: make and submit work

**1. Start from the assigned item**

Open the right shot list and phase sequence. Read the brief, current submission, last approved take, unresolved comments and approved Character/Location/Prop attachments. Check the intended canvas/group before starting. A new date, green tag or rightmost card does not establish the approved version.

**2. Work in a dated, initialed round group**

Use one named shot, character or reference view per row. Iterate left to right within that row. Use the Reference Sandbox for contextual sources or experiments; keep the production reference's exact library/take link visible. Preserve manual placement. Never use Organize group or Tidy up on an artist's layout.

Group name: YYYY-MM-DD - scope/item - R##[-B##] - initials. Example: 2026-10-13 - LOC-LocationA - R01-B02 - AB. Include the phase when a canvas contains multiple kinds of work. Use the date the pass began. Initials identify who made the pass; the current assignee and handoff identify who owns the next step.

R00 is the initial pass; R01 is a feedback revision. Start R01 only for items needing changes. Keep unchanged approvals in their existing sequence slots. If a row becomes unwieldy after many attempts, continue the same round in B02 rather than making a huge endless row. Collapse finished groups or use the Archive area deliberately; retain history and its source links.

**3. Use canvas tags for working choices**

In Progress — actively being developed. Interesting — promising alternate. Rejected — discarded attempt. Needs Review — working review marker. Final — the artist's nominated choice. These are shared project tags; filter by Author when reviewing your own work. Final does not grant official approval.

**4. Submit the exact take to its review item**

Use the take's Select for control, choose the correct sequence and named item, or have your agent assign that existing take to the verified shot ID. Confirm the shot list as well as the sequence. Assignment keeps the work on its canvas; it does not require downloading and uploading another copy.

In Production/Shot Info, deliberately show the nominated take and set the item to Needs Review. Add what changed, what needs a decision and the exact version/take link. Record the candidate separately from the last valid approved take. Only nominate useful choices; the sequence is the review queue, not the full generation history.

Reference review items follow the same path. After approval by the configured reference approver, attach the exact approved take to the appropriate Character, Location or Prop variation. A four-view location set may combine three unchanged R00 approvals with one revised R01 approval.

**5. Keep the recipe and close the shift**

Use File View's prompt/settings and Reuse as the starting point. Save the effective prompt, model, settings, exact reference IDs and their roles, parent takes, start/end frames, motion or edit source, and the actual mode used. Recheck bindings after Reuse. Save external Blender, Photoshop or ComfyUI source revisions and recipe/workflow paths. A copied prompt alone is not a complete handoff.

Before logging off, update Notes with the current candidate, last approval, active group, recipe, open comments, dependency/blocker, next action and next owner. Include live job IDs if rendering is still underway. Another artist should be able to resume from Preview without searching private chats.

## 03 — Review: comments and decisions

**Leave feedback where the exact work lives**

For generated takes, open File View → Comments and pin feedback to the relevant part of the image. Canvas comments can be attached to a file or placed beside a group; drawings/arrows/boxes are available there. Use the Comments sidebar to find threads, reply in the original thread and tag the intended artist when useful.

File View pins are supported for generated takes, not reference/library images. For those sources, leave a canvas comment beside the exact reference and include its link/ID. Use Production Notes for the item-level brief, decision summary and next action; keep visual discussion attached to the take.

Write actionable feedback: “SH08 v003 — keep this framing; warm the lighting and remove the background person.” State what stays, what changes, who owns the change and whether it blocks approval. For video, include a timecode. Resolve a thread after the requested fix has been checked; a rendered new take does not by itself resolve feedback.

**Use official statuses on the sequence's items**

To Do → In Progress → Needs Review → Internally Approved → Final Approved.

Changes Requested — reviewer names the changes and next owner. Blocked — a dependency prevents progress; record what is needed and who can unblock it. Archived — historical/inactive item.

The designated internal reviewer grants Internally Approved. The configured reference approver grants final reference approval; the configured final creative approver grants final shot approval, each for the exact take, phase/state and current brief. Record the decision with reviewer, date and evidence link. The producer or agent may record that decision, but must not invent it. A reference or first-frame approval does not automatically approve a later animation.

On revisions, nominate the new candidate to the same item and return it to Needs Review. Keep prior approval evidence. If requested changes invalidate the earlier take for the current brief, explicitly mark it unsuitable for current delivery. An optional exploration can leave a valid approved take in place while the new candidate is reviewed.

**Keep two explicit choices in Notes**

CURRENT SUBMISSION: exact take/version/link + current review status.

LAST APPROVED: exact take/version/link + phase + decision evidence + valid for current brief: yes/no.

Do not rely on the displayed alternate alone: it can change as someone browses takes. A reference baseline is a recorded approved set and snapshot; this workflow does not depend on a native sequence lock.

## 04 — Producer: presentations and delivery

**Find the current work through Production**

Open the correct scope shot list. Use Shotlist for ownership/status/notes, Storyboard for a visual overview and Kanban or status filters for the review queue. Check the required phase sequence. Saved views such as Needs Internal Review, Awaiting Director, Changes Requested and Final Approved make repeat checks faster.

For a presentation, take media from the exact nominated item/take. Check its version and status first. A review deck may contain pending work when clearly labeled “Needs Review” or “Internally Approved.” Record the Preview link and take/version alongside the slide or package manifest so feedback returns to the same asset.

Leave feedback in the take's comment thread, then summarize the action and owner in Production Notes. Use @mentions where appropriate. If a designated approver decision arrives in a meeting or elsewhere, record its source, date and exact take before changing the official status. A Slack notification or presentation link should point people back to this record.

**Package the approved work**

1. Check required coverage and valid configured final approval for each item being released. A review presentation and a final release have different approval requirements.

2. Confirm the displayed/selected take matches the recorded approved ID before download or sequence export. Preview export follows the displayed choice. Use Selected takes for the intended package; stacked alternates are for an agreed internal handoff.

3. Save a new dated, versioned Suite package with the media, a manifest mapping filenames to Preview take IDs, approval evidence and recipe/source links. Include the agreed format, resolution, frame rate, audio and any review burn-in. Verify the files are readable.

4. Update the stable review index. Keep “current review” and “last approved” pointers separate, and retain earlier packages. Scope comes before date in filing: job / script-or-location / phase / package-round-date.

5. Track prepared, exported, sent and accepted separately. The producer owns release; exporting a ZIP does not prove delivery or acceptance.

For Final VFX, record the agency graybox source clip, shot bounds, frame rate and handles. Its real acting, timing, gestures, eyeline and camera behavior are the performance source. Approved environment references define appearance and space. Keep those input roles explicit in the shot brief and recipe.

## 05 — Names and handoffs

**Media filename**

Client_Script_Item_v###_YYYYMMDD.ext

Item is a stable shot ID or Type-Description: SH08, CHAR-PersonA, LOC-LocationA or PROP-Helmet. CHAR/LOC/PROP already identify references. Temporary exploration uses LOOKDEV-Description. Do not add a separate SHEET, REF or phase field. Use COMMON for assets shared across scripts.

Examples: CLIENT_ScriptA_SH08_v003_20261013.mp4 · CLIENT_ScriptA_LOC-LocationA-Wide_v004_20261013.png · CLIENT_ScriptA_CHAR-PersonA_v002_20261013.png.

Increment the version per named item across phases; use its creation date. The phase belongs in the sequence and Suite folder. Location based canvases do not change the Script field in filenames. Preview's export numbering may be positional; map exported names to stable IDs with the manifest rather than treating row numbers as script shot numbers.

**Copy this handoff into item Notes**

CURRENT SUBMISSION: [take/version/link/status or none]

LAST APPROVED: [take/version/link/evidence; valid for current brief yes/no or none]

ACTIVE WORK: [canvas/group link; R##/B##; artist initials]

RECIPE / SOURCES: [prompt/settings/ref bindings; parent take IDs; native source/workflow paths]

OPEN FEEDBACK / BLOCKER: [comment links; dependency; who can resolve]

NEXT ACTION / OWNER: [specific next step; assigned artist/reviewer]

LIVE JOBS / UPDATED AT: [IDs if running; timestamp]

## 06 — Working with your agent

**Lead setup request**

“Read this workflow guide and the creative script. Set up [project] for [phases] and [scripts/locations]. Build the matching canvases, shot lists, sequences and named review items; fill briefs and references; assign the agreed artists. Preserve existing canvas layouts. Report missing decisions and verify the resulting records. Do not generate media.”

**Artist handoff request**

“Read [item]'s Notes, comments, current take and approved references. Recover its full recipe. Prepare the requested change in [canvas/group], preserve the last approved choice, and record the new candidate and handoff. Confirm the current model/settings/inputs and authorized run scope before generation.”

**Producer check request**

“Audit [shot list/phase] for current nominated takes, missing coverage, unresolved feedback and valid final approvals under the project policy. Prepare a review package or approved release manifest as specified, with exact take IDs and recipe links. Report exported, sent and accepted as separate states.”

Agents maintain the shared Preview records and reconcile the package manifest. They should use supported CLI/MCP tools for data and the normal UI for features absent from those tools. They must re-read shared Notes before edits, preserve manual layout and avoid treating tags, completion or provenance as human approval.

**Before the first production run**

The lead confirms actual names/counts, owners/reviewers, shot briefs, required reference coverage, Suite root and delivery specs. The template's sample people, locations, shots, durations and groups are examples; adapt them before relying on them for a real job.
